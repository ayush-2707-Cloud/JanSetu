1. ADD A FLOATING "BACK TO TOP + ACTIVE STEP" FAB BUTTON
────────────────────────────────────────────────────────
Why:  The roadmap page can get very long (7-10 steps with bottom panels).
      Users lose context scrolling through helplines, progress tracker, etc.
What: A small floating action button (bottom-right corner) that:
      • Shows "↑ Back to Top" when scrolled past the header
      • Shows "→ Go to Step 3" (the current IN_PROGRESS step) always
How:  A 48x48 pill button with useEffect scroll listener + scrollIntoView.


2. ANIMATE THE TIMELINE PROGRESS ON FIRST LOAD
────────────────────────────────────────────────
Why:  Currently the vertical connecting stem lines just appear statically.
      An entrance animation creates a premium "wow" moment.
What: When the Roadmap page mounts, the green stem line should animate
      downward from Step 1 to the current active step over ~1.5 seconds.
How:  CSS @keyframes on the stem div height, triggered by an
      IntersectionObserver or a simple mount animation class.


3. ADD CONFETTI / CELEBRATION EFFECT WHEN A STEP IS COMPLETED
─────────────────────────────────────────────────────────────
Why:  Marking a step "Completed" is a big deal for the user (real legal
      milestone). There's zero celebration feedback right now.
What: A burst of confetti particles (2-3 seconds) when clicking
      "Mark as Completed" in the InstructionDrawer footer.
How:  Use canvas-confetti (tiny 3KB library) or a pure CSS particle
      animation triggered on the toggleStepStatus callback.


4. REPLACE GOOGLE FONTS CDN WITH next/font FOR PERFORMANCE
──────────────────────────────────────────────────────────
Why:  layout.tsx currently loads Inter via an external <link> tag to
      fonts.googleapis.com. This is a render-blocking request and also
      sends user IP data to Google.
What: Use Next.js built-in next/font/google to self-host Inter.
      Eliminates the external network request, improves LCP by ~200ms.
How:  import { Inter } from "next/font/google" in layout.tsx, apply
      the className to <body>. Remove the three <link> tags in <head>.


5. ADD A "PRINT MY ROADMAP" BUTTON WITH A PRINT-OPTIMIZED STYLESHEET
─────────────────────────────────────────────────────────────────────
Why:  Many citizens visiting government offices need a physical printout
      of their step checklist and required documents.
What: A "🖨 Print Roadmap" button in the MilestoneRoadmap header that
      triggers window.print() with a @media print CSS that:
      • Hides header, footer, sidebar panels, AI chat
      • Shows all steps expanded (even locked ones)
      • Renders document checklists with empty checkboxes
How:  A @media print block in globals.css + a PrintButton component.


6. ADD SKELETON LOADING STATES FOR THE LANDING PAGE CARDS
─────────────────────────────────────────────────────────
Why:  When switching journeys or filtering domains, there's a brief
      moment where content pops in. This feels janky.
What: Skeleton placeholder cards (pulsing grey rectangles) shown for
      200-300ms before real content renders.
How:  You already have ui/skeleton.tsx built. Wrap GoalDiscoveryLanding
      cards in a Suspense boundary or use a loading state boolean.


7. ADD A "RECENTLY VIEWED JOURNEYS" SECTION ON THE LANDING PAGE
───────────────────────────────────────────────────────────────
Why:  Returning users have to re-find their journey every time. There's
      no memory of what they were working on.
What: A small horizontal scroll row at the top of GoalDiscoveryLanding:
      "📋 Continue Where You Left Off" showing 3-5 recently viewed
      journey cards with their progress percentage.
How:  Store journeyId + timestamp in localStorage via useLocalStorage
      hook (already exists). Read on mount and render mini cards.


8. MAKE THE INSTRUCTION DRAWER RESIZABLE (DRAG-TO-WIDEN)
────────────────────────────────────────────────────────
Why:  The drawer is fixed at max-w-xl. On large monitors, users may want
      to see more document details. On tablets, it covers too much.
What: A subtle drag handle on the left edge of the drawer that allows
      resizing between 380px and 800px width.
How:  A 4px vertical bar with cursor: col-resize + mouse event handlers
      for drag. Store preferred width in localStorage.


9. ADD KEYBOARD SHORTCUTS FOR POWER USERS
────────────────────────────────────────
Why:  Government clerks and frequent users will navigate the tool daily.
      Keyboard shortcuts make them 3-5x faster.
What: • Escape → Close drawer/modal
      • ↑/↓ arrows → Navigate between steps (already mentioned in plan)
      • Enter → Open selected step's drawer
      • 1/2/3/4 → Switch drawer tabs
      • Ctrl+K → Focus search bar
How:  A global useEffect keydown listener in MilestoneRoadmap component.
      ESC already works for the drawer. Add the rest.


10. ADD AN "ESTIMATED COMPLETION DATE" CALCULATOR
─────────────────────────────────────────────────
Why:  JourneyProgressTracker shows "~5 days remaining" but doesn't say
      WHEN. Users want a concrete target date.
What: Show "Estimated completion: 24 Aug 2026" calculated from today's
      date + remaining estimated days across incomplete steps.
How:  A simple Date calculation in JourneyProgressTracker:
      new Date(Date.now() + remainingDays * 86400000).toLocaleDateString()


11. ADD TOAST NOTIFICATIONS FOR USER ACTIONS
────────────────────────────────────────────
Why:  When users copy a link, bookmark a journey, or complete a step,
      there's no lightweight confirmation feedback (only page changes).
What: Minimal toast notification (bottom-center, auto-dismiss in 3s):
      "✓ Link copied to clipboard"
      "✓ Step 3 marked as completed"
      "⭐ Journey bookmarked"
How:  A ToastProvider context + CSS-animated toast component. No
      external library needed (Sonner or react-hot-toast are <5KB if
      you prefer a library).


12. ADD A "JOURNEY DIFFICULTY RATING" VISUAL INDICATOR
─────────────────────────────────────────────────────
Why:  Some journeys have 3 easy online steps, others have 10 steps
      requiring physical visits. Users should know upfront.
What: A difficulty badge on each goal card in GoalDiscoveryLanding:
      🟢 Easy (1-3 steps, all online)
      🟡 Moderate (4-7 steps, mixed)
      🔴 Complex (8+ steps, physical visits required)
How:  Derive from step count + whether any step has no actionUrl
      (meaning it requires physical presence).


13. ADD DARK MODE TOGGLE ANIMATION (SMOOTH TRANSITION)
─────────────────────────────────────────────────────
Why:  Currently switching dark/light mode causes an abrupt flash as
      all colors change simultaneously. Feels harsh.
What: A smooth 300ms cross-fade transition on the entire page when
      toggling theme.
How:  Add `transition-colors duration-300` to the <html> or <body>
      element. The existing component-level transition-colors classes
      will cascade naturally.


14. ADD STATE/CITY SELECTOR FOR LOCATION-SPECIFIC JOURNEYS
──────────────────────────────────────────────────────────
Why:  Legal processes in India differ by state (e.g., BBMP in Karnataka
      vs. BMC in Maharashtra). The current data is Bangalore-specific
      but doesn't let users switch context.
What: A dropdown in the header or landing page: "📍 Your Location:
      Bangalore, Karnataka ▼" that filters journeys and adjusts
      government portal links per state.
How:  Add a `location` field to JourneyContext. Filter mockJourneys
      by state tag. Future: backend handles location-aware data.


15. ADD A DOCUMENT UPLOAD PREVIEW ZONE (VISUAL PREPARATION)
───────────────────────────────────────────────────────────
Why:  The DocumentChecklist shows what's needed but doesn't help users
      organize their files before starting the process.
What: A drag-and-drop zone under each document requirement where users
      can "stage" their files locally (stored as base64 in localStorage
      or just filename references). Shows a ✅ check when a file is
      attached. Pure frontend — no upload to server.
How:  HTML5 File API + FileReader for thumbnail preview. Store metadata
      (filename, size, timestamp) in localStorage keyed by document ID.


16. ADD AN ACCESSIBILITY SCORE INDICATOR
───────────────────────────────────────
Why:  This is an SIH (Smart India Hackathon) project. Judges will look
      for accessibility compliance (WCAG 2.1 AA).
What: Ensure every interactive element has:
      • aria-label or aria-labelledby
      • Visible focus rings (already partially done)
      • Color contrast ratio ≥ 4.5:1 for text
      • Skip-to-main-content link at the top
How:  Add a <a href="#main" className="sr-only focus:not-sr-only">
      Skip to main content</a> as the first element in layout.tsx.
      Audit all buttons/links for aria labels.


17. ADD JOURNEY COMPARISON VIEW ("COMPARE 2 PROCESSES SIDE-BY-SIDE")
────────────────────────────────────────────────────────────────────
Why:  Users often need to compare two related processes (e.g., "Basic
      FSSAI Registration vs. State FSSAI License" or "Pvt Ltd vs. LLP").
What: A "Compare" checkbox on goal cards → opens a split-screen view
      showing two journeys side-by-side with step counts, costs, time,
      and document requirements compared in a table.
How:  A ComparisonModal component that takes two UniversalJourney
      objects and renders a diff-style table.


18. ADD A "JOURNEY TIMELINE EXPORT" (PDF / IMAGE)
────────────────────────────────────────────────
Why:  Users want to share their progress with lawyers, CAs, or family
      members who don't have access to the website.
What: An "Export as PDF" button that generates a clean single-page PDF
      of the roadmap with all steps, statuses, and document checklists.
How:  Use html2canvas + jsPDF (both lightweight) to screenshot the
      roadmap container and convert to a downloadable PDF.
      Alternative: Use the browser's built-in print-to-PDF.


19. ADD MICRO-INTERACTIONS ON STEP STATUS CHANGES
────────────────────────────────────────────────
Why:  When a step transitions from IN_PROGRESS → COMPLETED, the visual
      change is instant and easy to miss. It should feel rewarding.
What: • The timeline node morphs from blue pulsing circle → green
        checkmark with a 400ms scale+bounce animation
      • The connecting stem line "fills" green downward over 600ms
      • The next locked step's node "unlocks" with a brief shake
How:  CSS transition-all + @keyframes bounce on the node divs.
      Use a state flag (e.g., justCompleted) to trigger the animation
      class for 1 second, then remove it.


20. ADD A "GOVERNMENT HOLIDAY CALENDAR" AWARENESS BANNER
───────────────────────────────────────────────────────
Why:  Many legal processes require physical office visits. Users waste
      trips when offices are closed for gazetted holidays.
What: A context-aware banner at the top of the Roadmap page:
      "⚠️ BBMP Zonal Office closed on 26 Jan (Republic Day) — plan
      your visit accordingly"
How:  A small holidays.ts data file with Indian gazetted holidays.
      Compare today's date against upcoming holidays within 7 days.
      Show a warning banner in MilestoneRoadmap if a relevant office
      has a holiday soon.
